\section{Phase I: Metric Extraction Pipeline}
\label{sec:phase1_pipeline}

Candidate metrics M1--M4 are computed off-chain from Git history and frozen tag windows.
The scripts are deterministic command-line programs: they consume declared CSV inputs and
write CSV outputs without manual editing. The centralized execution consumes
\path{data/dataset_freeze_all.csv}, \path{data/versions_all.csv}, and
\path{data/windows_all.csv}. Pilot-specific files remain in the workspace for traceability,
but the suffixed \texttt{\_all} artifacts are the final Phase I evidence base.

\subsection{Primary CSV outputs}
\label{sec:phase1_outputs}

\begin{itemize}[leftmargin=*]
  \item \path{out/loc_per_tag_all.csv}: per (project, tag) snapshot size with total, blank, comment, and code lines.
  \item \path{out/metrics_window_dev_all.csv}: per (project, window, developer) commits, added/deleted lines, churn, binary-file count, activity days, and first/last committer timestamps.
  \item \path{out/metrics_window_totals_all.csv}: per (project, window) totals and unique-author counts.
  \item \path{out/metrics_window_dev_clean_all.csv} and \path{out/metrics_window_totals_clean_all.csv}: validated clean datasets used as the all-account audit baseline.
  \item \path{out/ownership_dev_shares_clean_all.csv} and \path{out/ownership_summary_clean_all.csv}: all-account ownership and concentration computed strictly from clean data.
  \item \path{out/metrics_window_dev_human_all.csv}, \path{out/metrics_window_totals_human_all.csv}, and \path{out/ownership_summary_human_all.csv}: human-only M3/M4 analysis population.
  \item \path{out/metrics_window_dev_human_normalized_all.csv} and \path{out/metrics_window_totals_human_normalized_all.csv}: duration-normalized human-only metrics.
  \item \path{out/window_duration_flags_all.csv} and \path{out/window_duration_sensitivity_summary_all.csv}: short-window flags and sensitivity thresholds.
  \item \path{out/bot_summary_by_project_all.csv}, \path{out/bot_summary_by_window_all.csv}, and \path{out/bot_identity_summary_all.csv}: automation impact summaries.
\end{itemize}

\subsection{Metric definitions (implementation-level)}
\label{sec:phase1_metric_impl}

\paragraph{M1 (LOC/SLOC).}
For each frozen tag commit, source files are counted and classified into blank, comment, and code lines. The centralized run
uses a multi-language policy documented in \path{data/loc_language_policy_all.csv}; it counts tracked source files for
the main languages of the ten repositories and excludes build, cache, dependency, and version-control directories. This keeps
M1 comparable as a source-size indicator while avoiding generated or vendored material where possible.

\paragraph{M2 (Churn).}
For each window $(from\_tag\rightarrow to\_tag)$, Git \texttt{numstat} output is used to sum lines added and deleted per developer.
Churn is defined as \texttt{added} $+$ \texttt{deleted}. Binary file changes are not assigned line counts, but they are retained
through \texttt{binary\_file\_count}.

\paragraph{M3 (Cadence).}
Cadence is represented by commit counts, activity days, and first/last committer timestamps per developer-window. Human-only cadence
outputs are the primary developer-behavior population. All-account cadence outputs are retained as an audit baseline because they
describe total repository activity, including automated updates.

\paragraph{M4 (Ownership and concentration).}
For each project-window, developer shares are computed as:
\[
share^{(churn)}_{d,w}=\frac{churn_{d,w}}{\sum_{d'}churn_{d',w}}, \quad
share^{(commits)}_{d,w}=\frac{commits_{d,w}}{\sum_{d'}commits_{d',w}}.
\]
The pipeline derives top-1/top-3 shares and Gini concentration values. Because M4 is intended to describe human maintainership
concentration, the primary M4 outputs are the human-only tables. All-account M4 remains useful for audit and sensitivity analysis.

\paragraph{Duration-normalized derived metrics.}
Release windows vary from less than one hour to more than one year. The pipeline therefore derives \texttt{commits\_per\_day},
\texttt{churn\_per\_day}, and \texttt{churn\_per\_kloc\_day}. Windows shorter than seven days are retained for traceability but
marked as \texttt{sensitivity\_only}. Phase II should not let these windows drive primary cadence conclusions.

\paragraph{Bot-sensitivity derived metrics.}
Automated accounts are explicitly labeled through \texttt{is\_bot}. The final centralized dataset flags six automation identities:
\path{dependabot[bot]}, \path{renovate[bot]}, \path{pre-commit-ci[bot]}, \path{pre-commit-ci-lite[bot]},
\path{autofix-ci[bot]}, and \path{BrewTestBot}. The bot-sensitivity outputs quantify their contribution and export a parallel
human-only population for M3 and M4.

\subsection{Error handling and traceability}
\label{sec:phase1_error_trace}

The extraction pipeline is fault-tolerant at repository-window granularity:
\begin{itemize}[leftmargin=*]
  \item Git command failures are appended to the corresponding \path{logs/*.log} file and processing continues where possible;
  \item cleaning, ownership, duration-normalization, and bot-sensitivity scripts write structured logs with row counts and validation outcomes;
  \item all derived tables are built from declared input files and script rules, not from manual spreadsheet edits.
\end{itemize}

This gives the report a reproducible audit trail: a reader can follow the dataset from frozen repositories and commits to clean,
human-only, normalized metric tables.
