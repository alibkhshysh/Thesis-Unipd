\section{Reproducibility Protocol and Data Lineage}
\label{sec:reproducibility}

\subsection{Artifact layout}
\label{sec:repro_layout}

Phase I artifacts are organized under a single workspace root, \texttt{Data,Outputs,Logs,Scripts/Phase 1/},
with fixed subdirectories: \texttt{data/}, \texttt{repos/}, \texttt{scripts/}, \texttt{out/}, and
\texttt{logs/}. The final evidence layer uses the \texttt{\_all} suffix. Pilot-only and extended-only
CSVs have been consolidated into the centralized files and removed from the active evidence layer.
The centralized \texttt{\_all} files are the inputs for the next phase.

All ten Git working copies are now colocated under the canonical \texttt{repos/} directory. Each repository
uses the official GitHub URL from \texttt{data/dataset\_freeze\_all.csv} as its \texttt{origin}. The layout
has also been validated against \texttt{data/versions\_all.csv}: all 80 frozen tags resolve to the frozen
commit hashes in the centralized repository folder. The validation record is stored in
\texttt{logs/canonical\_repos\_validation.log}.

\subsection{Execution protocol}
\label{sec:repro_execution}

The pipeline is deterministic given the frozen version and window files. A full rerun follows this order:
\begin{enumerate}[leftmargin=*]
  \item freeze repository metadata in \path{data/dataset_freeze_all.csv};
  \item freeze stable tags and commit hashes in \path{data/versions_all.csv};
  \item build consecutive tag-to-tag windows in \path{data/windows_all.csv};
  \item run \texttt{scripts/extract\_window\_metrics.py} to generate developer-window and window-total rows;
  \item run \texttt{scripts/clean\_round1\_metrics.py} to canonicalize developer rows and recompute clean totals;
  \item run \texttt{scripts/compute\_loc\_per\_tag\_multilang.py} for M1 snapshot-size evidence;
  \item run \texttt{scripts/recompute\_ownership\_from\_clean.py} for M4 concentration evidence;
  \item run \texttt{scripts/compute\_bot\_sensitivity\_outputs.py} to export human-only and bot-sensitivity tables;
  \item run \texttt{scripts/compute\_duration\_normalized\_metrics.py} for per-day, per-KLOC-day, and short-window flags;
  \item verify row counts and validation logs before using the outputs in Phase II.
\end{enumerate}

\subsection{Automated validation evidence}
\label{sec:repro_validation}

Validation evidence is recorded in log files and confirms that:
\begin{itemize}[leftmargin=*]
  \item duplicate-key groups merged in cleaning: 0;
  \item windows with zero total churn: 0;
  \item windows with zero total commits: 0;
  \item windows failing share-sum validations: 0;
  \item windows failing unique-author consistency checks: 0;
  \item all-account total mismatches found during bot-sensitivity validation: 0;
  \item windows shorter than seven days and flagged as \texttt{sensitivity\_only}: 22;
  \item bot rows retained for audit: 55; human-only rows exported for primary M3/M4 analysis: 1063.
  \item canonical repository-layout validation: 10 repositories checked, 80 frozen tag rows checked, 0 missing or mismatched commits, and 0 missing or mismatched tags.
  \item pilot-only cleanup: 32 superseded pilot CSV/log files removed after their evidence was consolidated into the centralized \texttt{\_all} layer.
  \item extended/scoped cleanup: 42 superseded extended CSV/log files and 8 duplicate scoped output folders removed after verification against the centralized \texttt{\_all} layer.
\end{itemize}

These checks establish that downstream Phase II analysis will operate on a coherent and fully auditable dataset.
