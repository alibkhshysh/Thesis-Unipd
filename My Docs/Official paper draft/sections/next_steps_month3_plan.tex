\section{Planned Next Phase: Comparative Metric Evaluation}
\label{sec:phase2_plan}

Phase II compares the candidate metrics using the criteria defined in
Section~\ref{sec:methodology_criteria}. The centralized Phase I artifacts are the evidence base,
so this phase focuses on metric behavior rather than additional dataset construction.
The first criterion, C1 stability, is reported in Section~\ref{sec:phase2_c1_stability}. Only after
the remaining comparative criteria are completed will the smart-contract feasibility rubric be applied
and one metric selected for the baseline proof-of-concept implementation.

\subsection{Phase II execution plan}
\label{sec:phase2_execution}

\begin{enumerate}[leftmargin=*]
  \item Complete criterion evidence for C2--C4 using the clean, human-only, bot-sensitivity, and duration-normalized \texttt{\_all} outputs, building on the completed C1 stability pass.
  \item Report both full-dataset results and robust results that exclude windows marked \texttt{sensitivity\_only} where duration-sensitive metrics are evaluated.
  \item Compare metric behavior across projects, ecosystems, and release-window lengths without selecting a PoC metric prematurely.
  \item Score smart-contract feasibility dimensions for each candidate using the predefined rubric.
  \item Select exactly one PoC metric using the decision protocol in Section~\ref{sec:decision_protocol}.
  \item Instantiate the selected metric inside the DESTINO-aligned metric-record blueprint in Section~\ref{sec:detailed_design_blueprint}.
\end{enumerate}

\subsection{Decision gate criteria}
\label{sec:phase2_gate}

The PoC metric will be selected only if it simultaneously satisfies:
\begin{itemize}[leftmargin=*]
  \item no feasibility exclusion criterion triggered under Section~\ref{sec:feasibility_rubric_full};
  \item acceptable comparative behavior under C1--C4 relative to alternatives;
  \item stable interpretation under bot-sensitivity and short-window robustness checks;
  \item reproducible extraction with no unresolved data-integrity issue.
\end{itemize}

This gate keeps implementation tied to the evidence, instead of choosing a metric because it is easy to compute
or attractive in one project only.
